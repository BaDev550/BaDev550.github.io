Tourqe

A custom C++ engine under the Tourqe::Engine namespace. It keeps the world-context feel of Unreal, without a full editor: one level editor, everything else written in the IDE.

reflect_gen.py Scene + ECS Render graph Level editor

Automated reflection

A Python generator, reflect_gen.py, reads TCLASS() and GENERATE_CLASS markers and writes a ReflectManifest.h. Types describe themselves, so editor and systems never hand-register anything.

  • TObject / TActor base classes
  • TCLASS() and TPROP() markup
  • Generated manifest, no runtime parsing

Scene, entities and components

Scene wraps an EntityFactory (generational handles, a 256-component signature bitset) and a ComponentRegistry of per-type storage, sparse-set style and keyed by std::type_index.

  • Cache-friendly component storage
  • ForEach<Ts...> iteration on Scene
  • WorldSubsystem owns the active scene; System classes run OnUpdate(Scene&)

Render graph

RenderSubsystem only initialises the RHI. Scene drawing lives in SceneRenderer2DSystem, a world system that builds passes as TCLASS RenderPass subclasses, ordered with Depends<>.

  • RHI init separated from scene rendering
  • Passes declare dependencies, the graph orders them
  • Built on my Vulkan renderer experience

Level editor only

The editor is deliberately small. It creates entities through WorldSubsystem's active scene, and all other tooling stays in code. That keeps the engine fast to iterate on and easy to reason about.

  • Entities created via the active scene
  • Components exposed by reflection
  • No full editor to maintain
